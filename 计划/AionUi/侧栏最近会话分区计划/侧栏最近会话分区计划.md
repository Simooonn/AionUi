# 1. Requirements Summary

1. 新分区「最近会话」位于「置顶」「置顶项目」之后、`afterPinnedContent`（团队）之前，即 `index.tsx:795` 与 `:798` 之间。
2. 来源 = `pinnedConversations` + 全部 workspace 组会话（含置顶项目）+ 无项目会话。排除工作区在失效集合里的会话；失效检查列表在原来的 `projectGroups` 之外，并入置顶会话的项目工作区。团队会话已由 `groupingHelpers.ts:102` 在上游过滤。
3. 排序：按 `getActivityTime`（`utils/chat/timeline.ts:31`）倒序，不限时间，也不限总数。
4. 分页：默认 5 条，「更多（还有 N 条）」每次加 5 条。折叠分区或重启后回到 5 条。分区的折叠状态沿用 `collapsedSections` 的持久化（key 在 `useConversations.ts:16`，写入在 `:181-187`）。
5. 行：
   - 不缩进；标题后接灰色项目名，无项目会话不显示。
   - 菜单 / 状态与原行一致，并且**菜单只在被操作的那一行弹出**。
   - DOM id 用 `rc-<id>`，保证全页面 `#c-<id>` 唯一。
6. 定位（修订后，附录 B）：
   - 最近会话里没有这条：原逻辑，逐字不变。
   - 最近会话里有这条：
     - 它的任何一行已完全可见：什么都不做。
     - 项目行已渲染：走原逻辑。
     - 其他情况：只滚动到最近会话那一行。
   - 以上任何情况都不会因为最近会话而展开项目。
7. 窄侧栏（`collapsed`）、批量模式（`batchMode`）、无候选时，整个分区不渲染。
8. 以下行为不变：Ctrl+Tab（`buildVisibleConversationIds` 及其滚动跟随）、目录徽标、批量全选、项目分页、全部展开 / 收起。
9. Non-Goals：时间窗口、去重、拖拽、把最近会话纳入 Ctrl+Tab、持久化已加载条数。

# 2. RALPLAN-DR 摘要（SHORT mode）

## Principles

1. **渲染结果是「可见」的唯一事实来源**：要判断最近会话里有没有某条，就直接看已提交 DOM 里有没有 `rc-<id>`，不在别处再算一遍可见性。折叠、批量、窄侧栏、已加载条数、失效排除这五个条件，都已经体现在「这一行渲染了没有」里。
2. **叠加，不改写**：最近会话是额外的只读视图。下面这些东西的代码路径和现有测试的断言**语义**都不变：
   - 既有分区、项目分页、Ctrl+Tab、徽标、批量；
   - 最近会话里不存在的会话，其定位逻辑。

   **唯一例外**：既有 `collapse-all` 用例里有一处全局行计数，最近会话行本来就不受「全部收起」影响，所以计数范围收窄为「项目行」。断言的意图（项目全部收起）不变。

3. **同一会话的两行，凡是逐行的 UI 状态都要各自独立**：DOM id 和菜单可见性各自持有。被选中、生成中、未读这类会话级状态则有意共享。
4. **零新增持久化**：已加载条数只放内存。唯一的写入沿用现有的 `collapsedSections` key。
5. **目录棘轮不恶化，fork 纪律不变**：
   - 源码只在 `utils/` 新增 1 个文件（6→7）；`GroupedHistory/`（10，已满）和 `hooks/`（9）不增加；测试放在 `tests/unit/conversation/sidebar/`（4→8）。
   - 改动现有文件一律包上 `// ace:` marker，并登记到 `ACE_CHANGES.md`。

**Architect 的综合建议（未采纳，作为后续项）**：在最近会话行的点击包装里记一个 `openedFromRecentRef`，作为可选参数传给 hook，用来修移动端（见第 4 节风险 R5）。未采纳的理由：移动端在点击的同一批更新里就会折叠侧栏（`Layout.tsx:467-470`），用户这时看不到侧栏，展开项目的副作用不可见；为这个边界在 hook 上加参数，收益低于复杂度。

### (c) 行的差异化（项目名、DOM id、菜单 key）

只有一个可行方案：DOM id 和项目名作为 `ConversationRow` 的可选 props；菜单 key 由 `index.tsx` 在传入 props 时加前缀。

**排除其他方案的理由**：

- 外包一层改不了内部根元素的 `id`（`ConversationRow.tsx:206`），也没法把项目名插进名称容器（`:280-298`）。

## Step 1 —— `G/utils/recentConversations.ts`（新文件）

```ts
export const RECENT_SECTION_KEY = 'recent';
export const RECENT_ROW_ID_PREFIX = 'rc-';

export type RecentConversation = { conversation: TChatConversation; projectLabel?: string };

/** Project workspace of a conversation, or undefined for a free conversation (same rule as groupingHelpers). */
export const getProjectWorkspace = (conversation: TChatConversation): string | undefined;

export const buildRecentConversations = (
  { pinnedConversations, timelineSections }: GroupedHistoryResult,
  staleWorkspaces: ReadonlySet<string>,
  t: (key: string) => string
): RecentConversation[];
```

- `getProjectWorkspace` 的判定与 `groupingHelpers.ts:36-40` 一致：只有 `extra.custom_workspace && extra.workspace` 同时成立才返回 `extra.workspace`。
- **workspace 组内的会话**：一律用 `workspaceGroup.workspace` 判断是否失效，用 `workspaceGroup.display_name` 作为 label。**不要**从会话的 `extra` 推导，因为既有测试的 fixture 没有 `extra`（`groupedHistoryProjectPaging.dom.test.tsx:117-118`）。
- **`type === 'conversation'` 的条目**：不带 label，也不参与失效判断。
- **`pinnedConversations`**：用 `getProjectWorkspace` 取工作区。
  - 有工作区：先判断是否失效；label 先查「workspace → display_name」映射（由上面的组构建），查不到再回退到 `getWorkspaceDisplayName(workspace, false, t)`（`groupingHelpers.ts:65` 用的也是它）。
  - 没有工作区：不带 label。
- **排序**：`toSorted((a, b) => getActivityTime(b.conversation) - getActivityTime(a.conversation))`。这是稳定排序，活跃时间相同时保持收集顺序（置顶 → 分区顺序）。
- 只做纯计算，不读 DOM。

## Step 3 —— `G/hooks/useConversations.ts`

1. 引入 `RECENT_SECTION_KEY`、`RECENT_ROW_ID_PREFIX`。
2. 新增状态 `const [recentLoadedCount, setRecentLoadedCount] = useState(PROJECT_PAGE_SIZE);`，不持久化。
3. 在 `toggleSection`（`:103-110`）的 updater 外面加一句 `if (key === RECENT_SECTION_KEY) setRecentLoadedCount(PROJECT_PAGE_SIZE);`。无论折叠还是展开，都回到 5 条（AC5）。
4. `handleShowMoreRecent = useCallback(() => setRecentLoadedCount((count) => count + PROJECT_PAGE_SIZE), [])`。
5. 新增模块级 DOM 工具 `isFullyVisible(element: HTMLElement): boolean`，放在 ace marker 内：
   - 高度 ≤ 0 时返回 `false`。jsdom 的 rect 全为 0，所以现有用例都会落到「不可见」，行为和现在一样。
   - 视口取最近一个 `getComputedStyle(...).overflowY` 为 `auto` 或 `scroll` 的祖先的矩形；找不到就用 `{ top: 0, bottom: window.innerHeight }`。
   - 返回 `rect.top >= bounds.top && rect.bottom <= bounds.bottom`。
6. 定位 effect（`:118-173`）：在 `if (revealedIdRef.current === id) return;` 之后，计算路径：

   ```ts
   // ace:start recent-section — the recent section only changes the reveal of
   // conversations it currently renders; everything else keeps the legacy path.
   const recentRow = document.getElementById(RECENT_ROW_ID_PREFIX + id);
   const projectRow = document.getElementById('c-' + id);
   const revealPath: 'legacy' | 'none' | 'recent' = !recentRow
     ? 'legacy'
     : isFullyVisible(recentRow) || (projectRow !== null && isFullyVisible(projectRow))
       ? 'none'
       : projectRow
         ? 'legacy'
         : 'recent';
   // ace:end
   ```

   - `legacy`：原代码逐字执行，包括 `locateConversation`、`if (!location) return;`、三个 setState 和双 RAF 滚动到 `c-<id>`。
   - `none`：只执行 `revealedIdRef.current = id`，不滚动，也不改任何状态。

# 6. ADR

- **Decision**：
  - 定位规则：DOM 探测（选项 A），加上三分支可见性分流（`legacy` / `none` / `recent`）。
  - 最近会话的已加载条数：放在 `useConversations`（b1）。
  - 行差异化：DOM id 和项目名用 `ConversationRow` 的可选 props；菜单 key 由 `index.tsx` 加 `rc-` 前缀。
  - 失效检查列表：并入置顶会话的项目工作区。
- **Drivers**：D1 跨 hook 可达性；D2 逐行状态独立；D3 既有行为与测试兼容（含 Ctrl+Tab 的滚动跟随）。
- **Alternatives considered**：
  - B：ref 桥；
  - C：把失效集合挪进 hook；
  - Architect 的 `openedFromRecentRef`（作为后续项）；
  - b2：用 effect 重置；
  - 包装组件，或复制一份行组件。
- **Why chosen**：A 是唯一一个既不重复计算可见性、也不改 hook 签名的方案。它依赖的提交保证由 React 文档化，并且已有 `c-` 的先例。三分支规则只改变「最近会话里存在」的那些会话的定位方式，其余会话逐字走原路径，同时满足 AC9（不展开项目）和 AC10（Ctrl+Tab 跟随不变）。
- **Consequences**：
  - hook 的定位行为依赖最近会话行在同一组件内渲染（R7）。
  - 行组件多了两个可选 props。
  - 已接受边界：移动端、失效集合晚到、掉出前 N 条（R4–R6），Ctrl+Tab 的残余差异（R9），sticky 标题遮挡（R10）。
- **Follow-ups**：
  - 如果移动端需要严格满足 AC9，再引入 `openedFromRecentRef`。
  - 如果将来要把最近会话纳入 Ctrl+Tab，需要先在 `buildVisibleConversationIds` 层面去重。
  - 记录 e2e 是否跑通。

# 附录 B：对规格的修订（2026-10-14，规划阶段）

规格 Constraints 中「定位规则」一条原文是：「若 X 在「最近会话」当前已渲染的行里…只滚动到最近会话的那一行」。

Critic 指出这条与 AC10「Ctrl+Tab……不变」冲突：Ctrl+Tab 通过路由切换会话，按原文，遍历到同时出现在最近会话前 5 条里的项目行时，侧栏会被拉回顶部；在项目区直接点击这类会话也会跳。

修订后的规则（已同步写进规格，随本计划一起待用户批准）：

- 最近会话里没有 X：原逻辑。
- 最近会话里有 X：
  - X 的任何一行已完全可见：什么都不做。
  - X 的项目行已渲染：走原逻辑（这时展开操作都是空操作）。
  - 其他情况：只滚动到最近会话那一行。

修订后的规则仍然满足 AC9（点击最近会话里的行不会展开项目），也满足 AC10 的主体。

**残余后果**（R9）：如果 X 的最近会话行可见，而它在项目里的那一行在屏外，Ctrl+Tab 切到 X 时不会把项目行滚进视野。当前会话仍在最近会话里高亮可见。这与原来的"滚动跟随"不完全一致，一并请用户确认。
