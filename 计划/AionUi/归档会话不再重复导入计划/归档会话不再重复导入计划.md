# 附录一：方案是什么

## §0 根因与目标（一段话）

`fetchExistingCliSessionIds`（`packages/desktop/src/process/ace/importCliSessions.ts:40-52`）用 `GET /api/conversations?limit=10000` 建"已导入"名单，后端该接口排除归档行（实测 181/187，归档 6 条缺席；`archived=true` / `include_archived=true` 被忽略）；`cli_session_id` 只是 `extra` JSON 字段、无唯一约束，主键 `id` 由后端生成，于是归档后的会话被当成新会话重新 `POST /api/conversations` 生成重复行。目标：名单改为只读直读 aioncore sqlite（天然含归档），命中归档会话**静默跳过、保持归档**；每次点击导入（含 0 条新会话时）末尾自动清理同 `cli_session_id` 的后到重复行，**保留最早导入的那条**，有应用内消息、cron 绑定或打开的内嵌终端的 loser **跳过并提示**，清理只走后端删除端点、绝不触碰本地 CLI 文件。

## §1 `packages/desktop/src/process/ace/aioncoreSchema.ts`（ace 自有文件，无需 marker）

1. **不修改** `ACE_AIONCORE_COUPLED_SCHEMA`（`:13-22`）与 `hasCoupledSchema`（`:33-46`）的行为：它是 `touchConversationActivity`（`:76`）、`backfillImportedConversationActivity`（`:101`）与 `sessionFiles.ts:125/169` 共享的闸门，扩列会让一次 schema 漂移同时拖垮本地文件解析（AC4 回归），也会让 `tests/unit/ace-cli-resume.test.ts:126-131` 的夹具失效。
2. 把 `:36-45` 的"白名单 + `PRAGMA table_info` + 列齐全"逻辑抽成私有 `tableHasColumns(db, table, cols)`；`hasCoupledSchema` 继续先做 `Object.hasOwn` 白名单再调用它。新增两组**按操作分开**的要求与检查：
   ```ts
   /** Baseline read only touches conversations.extra. */
   export const ACE_IMPORT_BASELINE_SCHEMA = { conversations: ['id', 'extra'] } as const;
   /** Duplicate cleanup touches ranking, archive state, live-turn and cron-binding checks. */
   export const ACE_IMPORT_DEDUPE_SCHEMA = {
     conversations: ['id', 'user_id', 'extra', 'created_at', 'archived_at'],
     messages: ['id', 'conversation_id'],
     cron_jobs: ['id', 'conversation_id'],
   } as const;
   export type ImportSchemaRequirement = typeof ACE_IMPORT_BASELINE_SCHEMA | typeof ACE_IMPORT_DEDUPE_SCHEMA;
   export function hasImportSchema(db: SqliteDb, requirement: ImportSchemaRequirement): boolean;
   ```
   `hasImportSchema` 只接受这两个常量对象（按引用判等做白名单），表名来自常量键，不接受外部字符串。`cron_jobs` 以线上 schema 为准：`conversation_id TEXT NOT NULL`。
3. `readImportedCliSessionIds(db: SqliteQueryDb): Set<string>`：
   ```sql
   SELECT json_extract(extra, '$.cli_session_id') AS sid
   FROM conversations
   WHERE json_type(extra, '$.cli_session_id') = 'text'
     AND json_extract(extra, '$.cli_session_id') <> ''
   ```
   无任何 `archived_at` 条件（名单天然含归档行）。用 `json_type` 而非 `typeof(json_extract(...))`：后者对 JSON 对象/数组型 sid 返回 `'text'`（Architect 夹具复验），`json_type` 对缺 key 返回 NULL、对对象/数组返回 `'object'`/`'array'`，均不入名单。
4. `findDuplicateImportLosers(db: SqliteQueryDb): DuplicateImportLoser[]`，`DuplicateImportLoser = { id: string; cliSessionId: string; archived: boolean; hasLiveTurns: boolean; hasCronJobs: boolean }`：

   ```sql
   SELECT r.id, r.sid AS cliSessionId,
          (r.archived_at IS NOT NULL) AS archived,
          EXISTS (SELECT 1 FROM messages m WHERE m.conversation_id = r.id AND m.id NOT LIKE 'cli-%') AS hasLiveTurns,
          EXISTS (SELECT 1 FROM cron_jobs j WHERE j.conversation_id = r.id) AS hasCronJobs
   FROM (
     SELECT id, user_id, archived_at,
            json_extract(extra, '$.cli_session_id') AS sid,
            ROW_NUMBER() OVER (
              PARTITION BY user_id, json_extract(extra, '$.cli_session_id')
              ORDER BY created_at ASC, rowid ASC
            ) AS rn
     FROM conversations
     WHERE json_type(extra, '$.cli_session_id') = 'text'
       AND json_extract(extra, '$.cli_session_id') <> ''
       AND json_extract(extra, '$.fork') IS NULL
   ) AS r
   WHERE r.rn > 1
   ORDER BY r.user_id, r.sid, r.rn
   ```

   - survivor = 每组 `rn = 1`（最早导入：`created_at INTEGER NOT NULL` 为导入时间，`backfill` 只改 `updated_at`，`:85-100`）。外层 `ORDER BY` 使输出确定有序（测试可按有序列表断言）。
   - 保护标记只在**外层**计算，不进入窗口输入，survivor 选择不受影响；"应用内消息"谓词与 `BACKFILL_IMPORTED_ACTIVITY_SQL`（`:95-97`）一致：`m.id NOT LIKE 'cli-%'`。
   - SQLite 的 `EXISTS` / `IS NOT NULL` 返回 0/1，TS 侧映射：`archived: Boolean(row.archived)`、`hasLiveTurns: Boolean(row.hasLiveTurns)`、`hasCronJobs: Boolean(row.hasCronJobs)`。
   - 按 `user_id` 分组（后端列表与删除均按用户隔离）；排除服务端打标的 fork 副本（`extra.fork`，v0.2.2 二进制字符串 "create: stripped client-supplied `extra.fork`"）；线上库实测 fork 行 0 条、单用户、按本 SQL 当前 loser 为 0，但 SQL 必须先天安全。
   - 畸形 `extra` JSON 会让 `json_type` 抛 `malformed JSON` → 走 `query-failed`（fail-closed；线上 0 行畸形；编排测试覆盖）。
   - 窗口函数与 `json_type`：better-sqlite3 12.8.0 与 Node 22 `node:sqlite` 均为 SQLite 3.51.3（`node_modules/better-sqlite3/deps/sqlite3/sqlite3.h:149`）。

5. 新增 `SqliteQueryDb = SqliteDb & { prepare: (sql: string) => { all: () => unknown[] } }`，不放宽现有 `SqliteRunDb`（`:55-57`）。

## §2 `packages/desktop/src/process/ace/importCliSessions.ts`（ace 自有文件）

1. `withBackendDb<T>(requirement, fn)`：`await import('better-sqlite3')` → `new BetterSqlite3(join(getDataPath(), 'aionui-backend.db'), { readonly: true, fileMustExist: true })`（先例 `parsers/opencodeParser.ts:56-57`）→ `pragma('busy_timeout = 5000')` → `hasImportSchema(db, requirement)` → `fn(db)`，`finally close()`。返回判别联合 `DbResult<T> = { ok: true; value: T } | { ok: false; reason: 'db-unavailable' | 'schema-mismatch' | 'query-failed'; detail: string }`。只读打开：读路径不可能写入、路径错误不会凭空建库、也避开现有读写打开（`:116/:156`）可能触发的关闭时 checkpoint；WAL 下读者不阻塞写者。
2. **替换** `fetchExistingCliSessionIds`（`:40-52`）为 `readImportBaseline(): Promise<BaselineResult>`，`BaselineResult = { ok: true; ids: Set<string> } | { ok: false; reason: 'db-unavailable' | 'schema-mismatch' | 'query-failed' | 'baseline-suspect' | 'list-failed'; detail: string }`：
   - `withBackendDb(ACE_IMPORT_BASELINE_SCHEMA, readImportedCliSessionIds)`；失败原样透传 reason/detail。
   - **空名单绊线**（替代原 `:111-133` 的反向守卫）：名单为空时调用一次 `ipcBridge.database.getUserConversations.invoke({ limit: 10000 })`；任一条的 `extra.cli_session_id` 为**非空字符串**（`typeof === 'string' && !== ''`，与 DB 谓词一致，不用 truthy）→ `{ ok: false, reason: 'baseline-suspect', detail: 'DB baseline empty but list reports imported rows' }`；HTTP 抛错 → `'list-failed'`。真正首次导入时两边都空 → 正常继续。已知残余：若 DB 读取已漂移且全部导入行都已归档，HTTP 列表看不到它们，绊线测不出；名单非空但不完整的漂移绊线也测不出（两者由名单侧 schema 闸门兜底）。
   - 删除旧的 HTTP 名单逻辑与 `existing.size === 0` 直查块；更新文件头注释 `:1-12`。
3. `scanCliSessions`（`:85-98`）：名单失败 → `console.warn('[ace:import] baseline unavailable', reason, detail)` 并返回 null（渲染层 `scanFailed`）；其余不变。
4. `importCliSessions(deps: ImportCliDeps)`（`:101-148`），`ImportCliDeps = { hasOpenTerminal: (conversationId: string) => boolean }`，由调用方注入，模块本身不引入 electron；同文件导出纯函数 `hasOpenTerminalIn(manager: { list(id: string): unknown[] } | null, id: string): boolean`（`(manager?.list(id).length ?? 0) > 0`），供 aceBridge 组装注入值并可单测：
   - 名单失败 → `failed = sessions.length`，`errors.push(\`aborted: imported-session baseline unavailable (${reason}: ${detail}) — not importing to avoid duplicates\`)`，`create` 零调用。
   - 导入循环不变（命中名单 → `skipped++`，含归档会话）。
   - 循环后、backfill 前执行 `cleanupDuplicateImports(result, deps)`：

     ```ts
     const losers = await withBackendDb(ACE_IMPORT_DEDUPE_SCHEMA, findDuplicateImportLosers);
     if (!losers.ok) {
       result.errors.push(`cleanup skipped: ${losers.reason}: ${losers.detail}`);
       return;
     } // 导入结果不受影响
     for (const l of losers.value) {
       const openTerminal = deps.hasOpenTerminal(l.id);
       if (l.hasLiveTurns || l.hasCronJobs || openTerminal) {
         result.duplicatesSkipped++;
         console.info('[ace:import] duplicate kept (protected)', { ...l, openTerminal });
         continue;
       }
       try {
         if (l.archived)
           await ipcBridge.sidebar.deleteArchivedItem.invoke({ item_type: 'conversation', item_id: l.id }); // DELETE /api/sidebar/archived/conversation/{id}, ipcBridge.ts:2573-2578
         else await ipcBridge.conversation.remove.invoke({ id: l.id }); // DELETE /api/conversations/{id}, ipcBridge.ts:308
         result.duplicatesRemoved++;
         result.removedIds.push(l.id);
         console.info('[ace:import] duplicate removed', {
           id: l.id,
           cliSessionId: l.cliSessionId,
           archived: l.archived,
         });
       } catch (e) {
         result.errors.push(`cleanup ${l.cliSessionId}: ${e instanceof Error ? e.message : String(e)}`);
       }
     }
     ```

     - 清理侧 schema 不匹配只记 `cleanup skipped`，**不阻断导入**（名单侧仍 fail-closed）。
     - 在导入循环**之后**重新查询 losers（本轮并发产生的重复也被兜底）。
     - 两个删除端点均为后端删除：会清 messages / acp_session / artifacts / snapshots，终止该会话 agent 进程，级联删除绑定的 cron 任务（附录三 R2）；因保护规则，实际被删的 loser 无应用内消息、无 cron 绑定、无打开的终端——但其置顶、改名（`name_source`）、项目/文件夹归属、`assistant_sessions` 关联等元数据会一并消失（已接受的后果，见 ADR）。**任何路径不调用** `process/ace/sessionFiles.ts`（`unlinkSessionFiles` / `resolveConversationFiles` / `resolveSessionFilePath` / `deleteOpencodeSessions` / `deleteOpencodeSessionRows`）与 `renderer/ace/deleteWithLocalFiles.ts`（`deleteConversationsWithFiles` / `deleteConversationsWithLocalData`），也不调用 `sidebar.deleteArchived`（一次清空整个归档，`ipcBridge.ts:2572`）或 `:2579-2597` 的项目归档/删除端点。
     - `remove` 返回值不做 `=== true` 判断（后端返回 `{success:true}` 无 data，`httpBridge.ts:281-285`）；不抛错即计数。

   - `result` 初始化 `duplicatesRemoved: 0, duplicatesSkipped: 0, removedIds: []`；backfill（`:150-165`）保持在清理之后。

## RALPLAN-DR 摘要（short mode）

**Principles**：① 单一事实源（名单来自含全部状态的 sqlite 表）；② 安全失败（名单拿不到/可疑即中止，绝不猜；清理只降级）；③ 删除面最小且可解释（只删"同用户、同 sid、非 fork、无应用内消息、无 cron 绑定、无打开的终端"的后到副本；只走后端删除端点；绝不碰本地文件）；④ 最小改动面 + fork 纪律（不新增 ace 文件、不改上游测试、登记）；⑤ 可验证（每条 AC 映射到能区分新旧行为的自动化用例或手工步骤，全量测试）。
**Decision Drivers**：① 闭源后端列表接口排除归档且不可改；② fork 已有直读 + 防御设施；③ 用户决策（静默跳过、自动清理、保留最早、保护有数据/有终端的副本、0 新会话也清理）。
**Viable Options**（两个独立决定：名单来源；清理策略）：
| 选项 | Pros | Cons |
|---|---|---|
| **名单-DB（选定）** 只读直读 `conversations`（含归档）+ 空名单绊线 | 名单完整、与归档状态解耦；读路径不可写；失败可诊断 | 新增私有 schema 耦合点（独立常量，不扩共享闸门） |
| 名单-B 列表 ∪ 归档接口分页拼接 | 不直读 DB | 分组读模型多轮分页、`limit=500` 实测 400、团队成员会话易漏；两套来源拼接是新的不一致源 |
| 名单-C `cli_session_id` 唯一索引 | 结构性杜绝 | 改 aioncore 私有 schema；fork 复制 extra 触发冲突 → 否决 |
| 名单-D 命中归档自动 unarchive | 不新建记录 | 推翻用户归档意图，Round 3 否决 |
| **清理-自动受保护（选定）** 导入末尾清理，三重保护，后端删除端点，渲染层释放 | 符合 Round 2/评审后决策；删除面可证明安全；清理故障只降级 | DELETE 有后端副作用（已限定在无数据副本，元数据仍会丢）；受保护副本会每次提示 |
| 清理-显式确认 | 删除面为零 | 违背 Round 2"自动兜底、不加 UI" |
| 清理-仅单飞互斥（预防不治疗） | 5 行代码堵住修复后剩下的唯一重复来源 | 不处理已存在/其他来源的重复；列为后续事项（不扩大范围） |

> 迭代历史（非备选）：v1 判定过宽（跨用户/空串/fork）、v2 统一闸门 + 漏 PTY 释放 + `typeof` 谓词可被对象穿透，均已修正。

## Pre-mortem（3 个失败场景）

1. **升级后全员中止**：aioncore 重命名 `extra` 或剥离自定义键 → 名单 `schema-mismatch` / 恒空触发 `baseline-suspect` → 每次导入 `scanFailed`；重命名 `cron_jobs` → 仅清理降级。应对：errors/日志含原因，升级清单含 schema 与非 schema 核对项。
2. **清理删过头**：排序/分组写错 → 每组删到 0 条或删掉有数据/有终端的副本。应对：单测 3（A/B/C/D + 他人 + fork + 对象 sid + 保护标记类型）、编排测试断言 `remove` 调用集合恰为无保护 losers 且三种保护各有用例；手工 3/4。
3. **误伤本地文件**：有人把删除改走 `deleteConversationsWithFiles` / `unlinkSessionFiles`，或误用 `sidebar.deleteArchived` 清空整个归档。应对：AC7 spy 反向断言（automock 全部导出 + 危险端点 0 调用）；代码注释与 ACE_CHANGES 写明只走两个单条删除端点。

## ADR

- **Decision**：（名单）导入去重名单改为主进程只读直读 aioncore `conversations` 表（含归档行），空名单时以 HTTP 列表做绊线；（清理）每次点击导入末尾用后端单条删除端点清理"同用户、同 `cli_session_id`、非 fork、无应用内消息、无 cron 绑定、无打开的终端"的后到重复副本，受保护副本跳过并提示，渲染层对被删 id 释放终端与命令队列。
- **Drivers**：闭源后端列表排除归档且不可改；fork 已有直读防御设施；用户要求静默跳过 + 自动兜底 + 保留最早 + 不丢用户数据/不打断终端。
- **Alternatives considered**：名单-B（列表∪归档接口拼接）、名单-C（唯一索引）、名单-D（自动 unarchive）；清理-显式确认、清理-仅单飞互斥。
- **Why chosen**：名单-DB 是在不改后端的前提下能保证名单完整的方案；清理-自动受保护符合用户决策，且删除面被限定到可证明安全；清理故障不影响主功能；改动集中在 3 个 ace 文件 + 类型/i18n/测试。
- **Consequences**：两组独立 schema 耦合常量 + 一个主进程注入点（`hasOpenTerminal`，当前休眠，面板重新移植后自动生效）；被删副本的置顶/改名/归属等元数据丢失；有数据或有终端的重复副本每次导入都会提示且目前没有安全的人工删除路径（需后续守卫）；0 新会话时点击导入也会执行清理并解析两遍 CLI 会话，且 backfill 每次点击都跑（终端侧续聊过的导入会话排序会暂时拨回，打开即自愈）；survivor 已归档时活跃副本会从侧栏消失；假设单用户（local 模式）。
- **Follow-ups（不在本次范围）**：主进程 `importCliSessions` 单飞互斥（从源头消除并发重复）；`resolveSessionFilePath` 共享引用守卫（同 sid 还有其他行时不解析文件路径）；受保护副本的手动合并工具；scan 结果复用；多用户模式下名单按用户过滤；导入按钮其余硬编码中文 i18n 化；永久删除时文件删除失败的忽略名单。

# 附录四：对规格的偏离（需你知晓）

1. 规格 Constraints 写"后端 DELETE 只清 conversations/messages/acp_session（DB-only）"——不成立，已改为"后端删除端点（含 agent 终止与 cron 级联、元数据丢失），并以保护规则限定被删副本无数据"。
2. 规格"survivor 之外其余为 losers 全部删除"——按你评审后的决定改为：有应用内消息或 cron 绑定的 loser 跳过并提示（新增 AC6b、`duplicatesSkipped`、`duplicatesKept` 文案）。
3. 规格"清理在每次 importCliSessions 末尾"——按你决定扩展到"扫描到 0 条新会话时也调用导入并清理"（`resolveScanAction` 的 `import-direct` 分支）。
4. 规格"HTTP 名单由 DB 直读取代"——保留一个仅在 DB 名单为空时触发的 HTTP 绊线（原则 2）。
5. toast 告警级别：`failed > 0 || duplicatesSkipped > 0 || errors.length > 0` 时 warning（规格只提 failed）；顺带修正 `aceBridge.ts:56` 异常时仍 success 的问题。
6. 规格建议"`ACE_AIONCORE_COUPLED_SCHEMA.conversations` 补 `created_at`"——改为独立的 `ACE_IMPORT_BASELINE_SCHEMA` / `ACE_IMPORT_DEDUPE_SCHEMA`，避免扩大共享闸门与破坏既有夹具；清理侧不匹配只降级。
7. 重复组定义收窄：仅"同 `user_id`、`json_type='text'` 且非空的 sid、`extra.fork IS NULL`"的行参与分组（规格只写"同 cli_session_id"）。
8. AC7 的端点集合：归档 loser 走 `sidebar.deleteArchivedItem`，活跃 loser 走 `conversation.remove`（规格只写 `DELETE /api/conversations/{id}`）；AC7 的验证方式为模块级 spy 反向断言。
9. 结果类型新增 `removedIds`，渲染层据此释放终端/命令队列（规格未提）。
10. 保护规则再加"打开的内嵌终端"（你两次确认：Critic 评审后决定加入；Architect 第 4 轮指出终端 UI 已于 `8ed831b84` 移除、此保护当前休眠后，你决定保留并标注休眠）；需要 `aceBridge.ts` 注入 `hasOpenTerminal`（`list().length > 0`，含已退出未关闭的终端），面板重新移植后自动生效。
11. fr-FR 连同既有 4 个 `importCli` 键一起补齐（规格未提的小范围扩展，为 check-i18n 消警）。
