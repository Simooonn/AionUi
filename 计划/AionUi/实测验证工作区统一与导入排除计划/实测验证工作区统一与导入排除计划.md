## §0 RALPLAN-DR 摘要（short 模式）

**原则（Principles）**

1. 单一判据、单一入口：排除规则只写一处纯函数，scan 与 import 走同一个 `parseAllCliSessions()`，不会出现"对话框说 N 条新会话、实际导入更少"。
2. 以原始 cwd 为准：判据作用于 `CliSessionMeta.workspace`（即 `extra.cli_cwd` 来源，`common/ace/types.ts:38-52`），不受 `resolveWorkspace()`（`importCliSessions.ts:152-155`）回落到 `homedir()` 的影响；判据不读文件系统（不 `realpath`），保持纯函数。
3. 与既有语义对齐——**两个标记都对齐**：`claudeParser.ts:20` 的 `AIONUI_INTERNAL_DIR_MARKERS = ['-Library-Application-Support-AionUi', '--aionui']` 对应两种路径形态（真实路径 / 符号链接逻辑路径），新判据用两条纯路径段规则复刻，不另造第二套语义；Claude 侧目录标记保留，新规则对 Claude 只是第二道兜底。
4. 不扩范围：不做系统临时目录过滤、不清存量、不改侧栏分组、不加用户可见文案（规格 Non-Goals）；Linux/Windows 的 app 内部数据根不在本次判据内（见风险表）。
5. 规约 + 兜底双保险：文档和记忆让代理不再乱建目录；代码过滤保证即使违规也进不了侧栏。

**决策驱动（Decision Drivers，前 3）**

1. 用户要求"侧栏完全不出现"，而 Codex/Gemini/opencode 三个 parser 没有任何内部目录排除（`codexParser.ts:24-40` 只丢 fork/subagent；`geminiParser.ts:109`、`opencodeParser.ts:102` 直接取 cwd/directory）。且各 CLI 记录 cwd 的方式不同：Claude、opencode 记解析后的真实路径（`/private/var/...`、`.../Library/Application Support/AionUi/aionui/...`），Codex 记传入的原样路径（`/var/folders/...`），Gemini 经 `projects.json` 哈希映射、两种形态都出现过——所以判据必须同时覆盖逻辑路径与真实路径。
2. 规格硬约束：现有 `tests/unit/ace-import-filter.test.ts` 与 `tests/unit/process/aceImportDedupe.test.ts` 不得改动（AC3），现有 Claude 目录标记保留；上游文件改动须按 fork 规则加标记并登记（`ACE_CHANGES.md:3`）。

```ts
// AionUi-internal workspaces must never be imported: the app's own ACP transcripts
// and the shared live-verification workspace (~/.aionui/live-verify) live there.
// claudeParser drops such project dirs by name marker; this is the backend-agnostic
// twin applied to the ORIGINAL cwd of every parsed session (codex / gemini /
// opencode carry no marker). Two path forms exist on macOS because `~/.aionui` is
// a symlink created by getDataPath (process/utils/utils.ts):
//   logical   …/.aionui*/…                              (as passed, e.g. codex)
//   resolved  …/Library/Application Support/AionUi*/…  (realpath, e.g. claude/opencode)
const AIONUI_DOT_DIR_PREFIX = '.aionui';
const AIONUI_APP_SUPPORT_PARENTS = ['Library', 'Application Support'] as const;
const AIONUI_APP_SUPPORT_PREFIX = 'AionUi';

/** True when the original CLI cwd lies in an AionUi-internal dir, in either path form. */
export function isAionUiInternalWorkspace(workspace: string | undefined): boolean {
  if (!workspace) return false;
  // Pure: normalise separators and `..` without touching the filesystem.
  const segments = posix.normalize(workspace.replace(/\\/g, '/')).split('/').filter(Boolean);
  return segments.some(
    (segment, i) =>
      segment.startsWith(AIONUI_DOT_DIR_PREFIX) ||
      (segment === AIONUI_APP_SUPPORT_PARENTS[0] &&
        segments[i + 1] === AIONUI_APP_SUPPORT_PARENTS[1] &&
        (segments[i + 2]?.startsWith(AIONUI_APP_SUPPORT_PREFIX) ?? false))
  );
}

/** Drop sessions whose original cwd is AionUi-internal; pure, shared by scan and import. */
export function filterImportableSessions(metas: readonly CliSessionMeta[]): CliSessionMeta[] {
  return metas.filter((meta) => !isAionUiInternalWorkspace(meta.workspace));
}

function parseAllCliSessions(): CliSessionMeta[] {
  return filterImportableSessions([
    ...parseClaudeCodeSessions(),
    ...parseCodexSessions(),
    ...parseGeminiSessions(),
    ...parseOpencodeSessions(),
  ]);
}
```

要点：

- `posix.normalize` 之前把 `\` 统一成 `/`，同时覆盖 POSIX 与 Windows 分隔符；`/x/.aionui/../proj` 归一为 `/x/proj` → 放行；`undefined` / 空串不排除（无 cwd 的会话仍按原逻辑回落到 `homedir()`）。

## §5 验证步骤（可执行判据）

**执行入口是同目录脚本 [`verify.sh`](verify.sh)**（v5 起取代内联 shell）。它自包含：`SCOPE`（本计划创建或修改的 6 个路径；其中新测试文件与本计划文档执行时可能还未被 git 跟踪）、基线位置（`.omc/state/live-verify/`，被 gitignore）、用户文件路径、记忆文件路径都写死在脚本里；每条 git 命令都内联 `-c core.quotePath=false`。所以分多次 Bash 调用执行、或执行者的 git 默认转义中文路径，都不会出错。

## ADR（终稿，决策自 v2 起未变）

- **Decision**：在 `importCliSessions.ts` 的 `parseAllCliSessions()` 统一丢弃"原始 cwd 为 AionUi 内部目录"的会话，判据为两条纯路径段规则（`.aionui*` 段；`Library`/`Application Support`/`AionUi*` 连续段），归一化后匹配；规约文档（带 `ace:` 标记）要求代理把实测验证会话统一建在 `~/.aionui/live-verify/`，缺链接时按 app 方式建链。
- **Drivers**：用户要求侧栏完全不出现；非 Claude parser 没有内部目录排除；各 CLI 记录 cwd 形态不一（符号链接 vs 真实路径）；既有测试不可改；上游文件改动须加标记登记。
- **Alternatives considered**：A 只认 `.aionui` 段（漏真实路径）、A″ 运行时 realpath（不纯、依赖文件系统）、A‴ 注入数据根（跨平台精确但需接线、dev 目标不稳定，列 Follow-up）、B 逐 parser 排除（四处接线无额外收益）、C 只在 import 循环过滤（scan 计数失真）、D 只写规约（Codex 仍导入）。
- **Why chosen**：单点、纯函数、scan/import 一致、parser 零改动、与 `claudeParser.ts:20` 的两个标记一一对应、macOS 两种路径形态全覆盖。
- **Consequences**：(1) parser 仍解析内部会话文件（代价可忽略）；(2) 规则 2 同时让 AionUi 自身在 `Application Support/AionUi*` 临时工作区里产生的 codex/gemini/opencode 会话不再可导入——这正是 Claude 侧标记的原意（"不要把 app 自己的输出当 CLI 历史喂回去"），本机存量 0 条受影响；(3) 基线中止时 `failed` 只计可导入数；(4) Linux/Windows 的 app 内部数据根不在判据内。
- **Follow-ups**：(1) 用户自行清理存量 26+5 条及其 `projects` 行（归档不删，或连原始文件一起删）；(2) 若要跨平台精确匹配，评估 A‴（注入 `getDataPath()` 数据根）；(3) Gemini 缺映射会话的处理。
