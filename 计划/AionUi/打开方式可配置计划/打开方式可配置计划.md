# 附录一：RALPLAN-DR 摘要

**模式**：SHORT（没有 `--deliberate`，也没有高风险信号；未做 pre-mortem）。

## 原则（Principles）

1. **默认即现状**：以下情况走的代码和改动前完全一致，也就是 aioncore `/api/shell/open-folder-with` 和内置浏览器 `openBrowserTab()`：
   - 未配置、配置的应用检测不到、启动失败（超时除外，见 R11）
   - 非 macOS、WebUI
   - 选择为空时，工作区下拉连已安装列表的 IPC 都不发。
2. **信任边界在主进程**：
   - 渲染端只传预设 id 和工作区路径。
   - 主进程按注册表解析应用路径。
   - 文件夹先 `realpath`，再校验是绝对路径的目录。
   - 启动用 `execFile` 加 argv 数组，argv 里放解析后的路径，不拼 shell 字符串。
3. **fork 隔离**：
   - 新逻辑放在 `common/ace/`、`renderer/ace/settings/` 和已有的 `process/ace/aceBridge.ts`。
   - 改上游文件时只加 `ace:start`/`ace:end` 块，并在 `ACE_CHANGES.md` 登记。
   - 不改 aioncore。
4. **每个预设都要标明依据**，注册表字段 `evidence` 取以下值：
   - `local`：本机 spike 实测通过。
   - `docs`：有官方文档或源码依据，argv 由单测钉住，但没有在本机跑过。
   - 两种依据都没有的应用不列入（Arc）。
   - 需要 `open -n` 另起实例才能设置 cwd 的终端也不列入（WezTerm、Alacritty）。
   - 本机已装、但 spike 没通过的应用，改用备选 argv；还不行就移出清单（附录二 §1.4）。
5. **IPC 和存储面最小**：
   - 新增 3 个 IPC 通道和 1 个 localStorage 键。
   - 不新增上游 `ipcBridge` 条目。

## 决策驱动（Decision Drivers，前 3 项）

1. **启动正确性**：目录确实被打开，终端的 cwd 确实是工作区，浏览器确实打开了窗口或标签。各应用的 `open` 语义不一样，这是最大的不确定性。
2. **上游合并安全，并遵守项目硬规则**：进程边界、i18n、ace marker、目录规模棘轮。`WorkspaceOpenButton.tsx` 在上游很活跃，近期有 #4202、#4069、#3826 三次提交。
3. **体验与延迟**：
   - 检测不等图标。
   - 下拉里显示真实图标。
   - 不出现点了没反应的项。
   - 列表加载完之前就点击，也要能启动所选应用。

## §1 实机 spike（待办 1）与预设清单

### 1.1 spike 做法

**执行前要做的事**

- 告知用户：spike 会在桌面上弹出真实应用窗口，副作用清单见附录三 V9.0。
- 所有命令的路径都用 `~/.aionui/live-verify`。

**逐个应用记录的内容**

1. 每条 argv 用 `time /usr/bin/open …` 记录耗时。这个耗时决定附录二 §3 的 5 秒超时是否合适。
2. 是否打开、是否新开了窗口：按附录三 V9 的窗口计数法（`CGWindowListCopyWindowInfo` 前后对比）判断。
3. 终端的 cwd：按 V9 的 `lsof` 前后对比判断。
4. 编辑器打开了哪个目录：截图后由用户目检。

**图标冷启动耗时**

- 在 `$TMPDIR` 写一个临时 Electron 探测脚本，不进仓库，跑完删除。
- 用 `performance.now()` 测 9 个应用首次调用 `createThumbnailFromPath(realpath, {width:64,height:64})` 的耗时，结论用于核对附录二 §2 的 2000ms 图标超时。

**3 个待定应用**

- **Antigravity 2.23.0**：`Info.plist` 里没有 `CFBundleDocumentTypes`，也没有自带 CLI（2026-10-15 已核对）。`open -a` 仍会强制把打开文档事件投递给它，但它会不会打开这个文件夹，只能实测。打不开就移出清单，并告知用户。
- **Safari**：`open -a Safari about:blank` 可能把 `about:blank` 当成相对文件路径，报 "file does not exist"。失败就换成 `['-a', <app>]`（只激活；没有窗口时会新建窗口）。
- **Firefox**：`open -n … -new-window` 可能弹出「已在运行」对话框。失败就换成 `['-a', <app>, 'about:blank']`（开新标签）。
- 这三个应用（含 Antigravity，若通过）最终采用的行为都要写进记录和 ACE_CHANGES（U4）。

### 1.2 搜索目录与迭代顺序

**搜索目录**（按以下顺序）：

1. `/Applications`
2. `~/Applications`
3. `~/Applications/JetBrains Toolbox`（旧版 Toolbox 的安装位置）
4. `/System/Applications`
5. `/System/Applications/Utilities`

**迭代顺序**：对每个预设，**目录在外层、bundle 名在内层**，取第一个是目录的命中。例如 IntelliJ 会先试 `/Applications/` 下的 4 个 bundle 名，再试 `~/Applications/` 下的 4 个。这样系统级安装优先。

### 1.3 启动方式（`launch.kind`）

所有 argv 都交给 `execFile('/usr/bin/open', argv, { timeout: 5000 })`。`<app>` 是解析出的 `.app` 绝对路径，`<dir>` 是 `realpath` 后的工作区路径。

| kind                 | argv                                                                                                                          | 适用                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `folder`             | `['-a', <app>, <dir>]`                                                                                                        | 所有编辑器；Terminal、iTerm2、Ghostty、kitty  |
| `warp-uri`           | `['-a', <app>, 'warp://action/new_window?path=' + encodeURIComponent(<dir>)]`                                                 | Warp                                          |
| `browser-new-window` | `['-n', '-a', <app>, '--args', <flag>, 'about:blank']`；`<flag>` 在 Chromium 系是 `--new-window`，在 Firefox 是 `-new-window` | Chrome、Edge、Brave、Firefox（以 spike 为准） |
| `browser-url`        | `['-a', <app>, 'about:blank']`，备选 `['-a', <app>]`                                                                          | Safari（以 spike 为准）                       |

## §2 `packages/desktop/src/common/ace/openWithApps.ts`（新增）

### 进程边界（R10）

- 这是纯 TypeScript 文件。
- 不从 `@/common` barrel 导入，也不导入 `node:path`、Node、Electron 或 DOM。
- 路径用字符串模板拼接；只在 macOS 上使用，所有路径都是 `/` 开头。
- 主进程和渲染端都会导入它，`common/ace/resumeCommand.ts` 是两端共用的先例。
- `createOpenWithService` 放在 common 的原因：`process/ace/` 已有 10 个子项，不能再加文件，而依赖注入的服务不含 IO，可以在 node 环境里单测。这一点要记进 ACE_CHANGES。

### 导出

**类型**

- `OpenWithCategory`：`'editor' | 'terminal' | 'browser'`
- `OpenWithLaunchSpec`：§1.3 四种 kind 的联合
- `OpenWithPreset`：`{ id; category; name; bundles: readonly string[]; launch; evidence: 'local' | 'docs' }`
- `OpenWithInstalledApp`：`{ id; category; name }`，**不含图标**
- `OpenWithSelection`：`Partial<Record<OpenWithCategory, string>>`
- `OpenWithLaunchRequest`：`{ appId: string; folderPath?: string }`
- `OpenWithLaunchResult`：成功为 `{ ok: true }`；失败为 `{ ok: false; reason }`，`reason` 取值：
  - `'unsupported-platform'`
  - `'unknown-app'`
  - `'not-installed'`
  - `'invalid-folder'`
  - `'launch-failed'`

**常量**

- `OPEN_WITH_SEARCH_DIRS`
- `OPEN_WITH_STORAGE_KEY = 'workspace-open-apps'`

**纯函数**

- `findOpenWithPreset(id: unknown)`：用 `Map` 查表，挡住 `__proto__` 这类原型链上的键。

### `createOpenWithService(deps)`

`deps` 包含：

- `platform`、`homeDir`
- `isDirectory(p)`、`realpath(p)`
- `thumbnail(realAppPath): Promise<string | undefined>`
- `runOpen(argv): Promise<'ok' | 'timeout'>`：超时时 resolve 为 `'timeout'`，其他失败时 reject

返回值包含下面三个方法。

**`listInstalled()`**

- 非 `darwin` 返回 `[]`。
- 按 §1.2 的顺序做 `stat`，**不取图标**，立即返回（R1）。
- 结果顺序与注册表一致。

**`loadIcon(rawAppId: unknown): Promise<string | null>`**

- id 不合法或应用未安装时返回 `null`。
- 先 `realpath`，再调用 `thumbnail`，超时 2000ms。
- **只缓存成功的 data URL**，按 realpath 存进 `Map<string, string>`。
- 进行中的请求放在一个 Map 里，结束后不论成败都删掉这一项。
- 超时、reject、得到空图都返回 `null`，不写缓存，下次调用会重试（R2）。

**`launch(raw: unknown)`**：按下列顺序检查，任何一步不通过就返回对应的 reason，并且**不调用 `runOpen`**。

1. 不是 `darwin` → `unsupported-platform`。
2. `raw` 必须是普通对象，`appId` 匹配 `/^[a-z0-9-]{1,32}$/` 且在注册表中，否则 → `unknown-app`。
3. 编辑器和终端还要检查文件夹（R4），否则 → `invalid-folder`：
   - 原始值是字符串，长度不超过 4096，不含 `\0`，以 `/` 开头。这一步做廉价预检，也防止相对路径按主进程的 cwd 解析。
   - `resolved = await realpath(raw)`，抛错就算不通过。
   - `resolved` 以 `/` 开头，并且 `isDirectory(resolved)` 为真。
   - **`isDirectory` 是唯一能阻止 Terminal、iTerm2、Ghostty 把文件当脚本执行的关卡**（`open -a Terminal x.sh` 会执行该文件），所以它不能省，也不能放宽。
   - 浏览器忽略 `folderPath`。
4. 当场重新检测安装位置，没装 → `not-installed`。
5. 调 `runOpen(buildOpenArgv(preset, appPath, resolved))`。argv 用的是**解析后的路径**。结果映射为：`'timeout'` → `launch-timeout`；reject → `launch-failed`；其他 → `{ ok: true }`。

## §4 渲染端 store 与 hook（`renderer/ace/settings/`）

### `useOpenWithApps.ts`：模块级 store

**快照与读取（R3）**

- **localStorage 键 `workspace-open-apps` 是唯一事实源**。
- `getSnapshot()` 每次调用都执行 `localStorage.getItem(KEY)`。原始字符串没变就复用上次解析出的 `selection`。
- 快照对象在 `(raw, installedRef, iconsRef)` 三者都不变时直接返回同一个引用，保证 `useSyncExternalStore` 引用稳定。
- `storage` 事件和 setter 只负责通知订阅者，不往 store 里写数据。
- 所以在同一窗口里直接 `localStorage.setItem` 也会生效：下一次渲染读到的就是新值。这也修好了第 1 稿 V9 第 6 步的问题。

**快照字段**

- `enabled`
- `selection`
- `installed: OpenWithInstalledApp[] | null`，`null` 表示还没加载
- `icons: Readonly<Record<string, string>>`

**`isOpenWithEnabled()`**：以下三条同时成立：

- `isElectronDesktop()`（`renderer/utils/platform.ts:18`）
- `isMacOS()`（同文件 `:26`）

`getApi()` 沿用局部窄类型断言的写法，与 `useImportCliSessions.ts:75` 一致。

**`refreshOpenWithApps()`**

- 拿到 `listInstalled` 后，按 id 列表做**结构比较**，只有变化时才替换 `installed` 的引用，避免每次打开下拉都重建快照。
- 对还没有图标的应用并行调用 `openWithAppIcon`，每到一个就补进 `icons`（替换引用）并通知订阅者（R1）。

**`launchOpenWithApp(tool, folderPath): Promise<boolean>`**（R5、R11）。返回 `true` 表示已处理，上游分支不再执行。

1. 没有所选应用 → `false`。
2. 调用 `openWithLaunch`；IPC 抛错时按 `launch-failed` 处理。
3. `ok` → `true`。
4. 其余情况都先执行 `void refreshOpenWithApps()`，再按 reason 分流：
   - `launch-timeout` → `true`。**不回退**，避免启动两次。
   - `tool === 'vscode'` → 调用 `ipcBridge.shell.checkToolInstalled({ tool: 'vscode' })`：
     - 有 `code` → `false`，回退到上游。
     - 没有 → `true`，什么都不做，列表刷新后这一项会隐藏，所以不会出现死项（AC5）。
   - 其他 → `false`，回退到上游分支。
