# hooks

## Purpose

React hooks backing the grouped conversation-history sidebar: they sync the live conversation list and its generating/unread state, manage batch selection and bulk export, handle pin drag-and-drop reordering, hold the workspace expand/collapse state plus each project's loaded-conversation count for the lifetime of the run (neither is persisted), and run per-conversation actions (open, rename, delete, pin, remove project).

## For AI Agents

- Renderer-only code: no Node.js APIs. All cross-process work goes through `ipcBridge` (`@/common`); side-channel UI updates use `emitter` (`@/renderer/utils/emitter`).
- Workspace view state flows one way: the owner `useConversations.ts` dispatches a `WorkspaceViewSnapshot`, and `useWorkspaceExpansionState.ts`/`useVisibleConversationIds.ts` read that same object through `useSyncExternalStore`. Nothing is persisted. Keep `useConversations` the only dispatcher, and keep `WORKSPACE_EXPANSION_EVENT` and the snapshot shape in sync across the three files.
- Projects start collapsed on every launch (spec AC7); do not reintroduce the first-load auto-expand-all behaviour (#1156). Revealing the active conversation expands only its own project, and raises that project's count to the smallest multiple of `PROJECT_PAGE_SIZE` covering the target row.
- The reveal effect asks `resolveRevealPath` first. A conversation the recent section renders (`#rc-<id>` in the DOM) never expands its project: nothing moves when any of its rows is fully inside the sidebar viewport, the legacy expand-and-scroll path runs when its own `#c-<id>` row is rendered (keeps Ctrl+Tab following), otherwise only the `rc-` row is scrolled. This reads the committed DOM, so the recent rows must stay rendered by the component that calls `useConversations` — moving them elsewhere breaks the same-commit guarantee. Accepted gaps: a stale project's conversation may lock the reveal on its recent row before the async stale set arrives, and a conversation revealed only through the recent section is not re-revealed after it drops out of the loaded rows.
- `useConversationListSync.ts` uses a whitelist of generating message types on purpose; extend the whitelist rather than switching to a blacklist so unknown/internal message types don't trigger false spinners.
- Drag sort orders are fractional (`computeSortOrder`); trigger `reindexSortOrders` only when `needsReindex` reports precision loss, then persist all affected rows.
