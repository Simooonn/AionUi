# 附录一：方案是什么

## 1. 两部分各自怎么工作

| 部分         | 做法                                                                              | 代码                                           |
| ------------ | --------------------------------------------------------------------------------- | ---------------------------------------------- |
| Release 邮件 | 上游仓库 Watch → Custom → 只勾 Releases，GitHub 发版时发邮件                      | 无                                             |
| 落后提醒     | fork `main` 上的定时 workflow，对比 fork main 与上游 main，落后就推一条 Lark 消息 | `.github/workflows/upstream-commit-notify.yml` |

## 2. workflow 要点

- **位置**：fork 的 `main`（默认分支）。定时任务只在默认分支运行；feature/ace 不受影响。
- **触发**：`cron: '17 */2 * * *'`（UTC，每 2 小时的第 17 分钟）+ `workflow_dispatch`（Actions 页 Run workflow 手动跑）。
- **判定**：`gh api repos/iOfficeAI/AionUi/compare/Simooonn:main...iOfficeAI:main`，`ahead_by` = 上游有、fork 没有的提交数。`ahead_by == 0` 不发。
- **无状态**：不记录推送过什么。fork 不同步，就每 2 小时重复提醒；同步后自动停止。
- **只看 fork main**：同步了 main 就不再提醒，不管是否合进了 feature/ace。
- **消息**：Lark `post` 富文本，一次一条。
  - 标题：`上游 iOfficeAI/AionUi 有 N 个提交未同步到 fork main`
  - 每行：`短sha  日期 时:分(UTC+8)  作者: 提交标题`，新的在前，最多 20 行；作者显示 GitHub 账号名（如 `IceyLiu`），提交邮箱没关联账号时退回 git 作者名（2026-10-22 起，原先显示 git 作者名如“瓦砾”）
  - 超过 20 个：加一行 `……另有 M 个更早的提交未列出`
  - 末尾：`查看全部差异` 链接到 GitHub compare 页
- **Lark 接入**：群自定义机器人 + 签名校验。签名 = base64(HMAC-SHA256(key = `timestamp + "\n" + secret`, 空串))。
- **失败即报错**：缺 Secret（点名缺哪个）、GitHub API 失败、Lark 返回非 0 或非 JSON、curl 失败 → step 失败，GitHub 给仓库所有者发失败邮件。不重试。
- **权限**：只有 `contents: read`，用 runner 自带 token；不 checkout、不用第三方 action，只用 runner 预装的 gh/jq/openssl/curl。

# 附录三：风险 / 其他

## 1. 两种会让提醒悄悄停掉的情况（不会有失败邮件）

1. **workflow 文件被同步操作删掉**：fork main 比上游多这 1 个提交。同步时：
   - 可以：网页 "Sync fork → Update branch"；不带 `--force` 的 `gh repo sync`；本地 `git merge upstream/main` 后推送。
   - 不可以：网页 "Discard N commits"；`gh repo sync --force`；`git reset --hard upstream/main` 后强推。
2. **60 天无活动自动停用**：public 仓库连续 60 天无活动，GitHub 停用定时任务。社区实测只有推到默认分支（main）的提交才算活动，推 feature/ace 不算。上游长时间没提交时，用附录一 §3 的命令查 `state`，是 `disabled_inactivity` 就到 Actions 页点 Enable workflow。

## 2. 其他已知取舍

- GitHub 定时任务可能延迟或丢弃个别触发；无状态设计下只是晚 2 小时提醒，影响可忽略。
- 同步后到下次检查之间不会发"已同步"消息，只是不再提醒。
- 提交标题特别长时，消息可能超过 Lark 20 KB 上限导致失败；同步后自然消失，没有截断标题。
- 日志用英文（"Fork main is in sync…"），和 spec 里的中文示例措辞不同，语义一致。
- 用户 fork main 以后的同步会产生合并提交（不再是快进），这是把 workflow 放 main 的已接受代价。
