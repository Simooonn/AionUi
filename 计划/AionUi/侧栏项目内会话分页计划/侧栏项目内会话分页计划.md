# 1. Requirements Summary

1. 每个项目文件夹（普通 + 置顶）展开后只渲染活跃时间降序的前 5 条会话；≤5 条时无"更多"行。
2. > 5 条时列表底部渲染一行"更多（还有 N 条）"，高 34px，点一次 +5，N=0 时该行消失。
3. 收起项目再展开，已加载条数回到 5；不做任何持久化。
4. 搜索弹层打开第 6 条之后的会话：自动展开该项目并把已加载条数推进到覆盖该会话（取 5 的整数倍），再滚动定位。
5. `buildVisibleConversationIds` 同步截断，Ctrl+Tab 不会跳到未渲染会话。
6. "项目"分组标题行右侧、刷新按钮旁新增"全部展开 / 全部收起"两个图标按钮，作用于全部项目（含置顶）。
7. 重启后所有项目默认收起：删除 `useConversations.ts:168-187` 的首次自动全展开，展开状态不从 `localStorage` 恢复。
8. 徽标（`index.tsx:480` 传 `group.conversations` 给 `renderFolderStatusBadges`，内部 `:371` 调 `collectFolderStatuses`）与批量全选（`useBatchSelection.ts:35`）继续基于全量会话，不受切片影响。
9. 质量门：13 语言 key 齐全、`bun run test`、`bunx tsc --noEmit`、lint/format、`i18n:types` + `check-i18n`。
10. Non-Goals：团队分组、搜索弹层列表、虚拟列表、持久化已加载条数、"展开全部会话"、置顶项目拖拽重排改动、Ctrl+Tab 跳到未渲染行。

# 2. RALPLAN-DR 摘要（SHORT mode）

## Principles

1. **单一状态源 + 单一输入边**：展开状态与已加载条数由同一个 owner 写出、经**一条**通道以**一个快照对象**发布；订阅侧用 `useSyncExternalStore` 由 React 负责"订阅后重读"。字段间半更新与挂载竞态两类问题都在结构上消除（AC5 的主要失效模式）。
2. **零新增持久化、零残留读路径**：`loadedCounts` 与 `expandedWorkspaces` 都只活在内存里，重启即归零；代码中**不存在**任何 `localStorage` 读或写路径（AC7）。
3. **目录棘轮不恶化**：`GroupedHistory/` 已满 10 项、`hooks/` 9 项（剩 1 格）、`utils/` 6 项（剩 4 格）→ 源码**零新增文件**。测试侧 `tests/unit/conversation/` 已 13 项、`tests/unit/renderer/conversation/` 已 23 项，**两者均已超限**，按 `docs/contributing/file-structure.md:174` 的补救方式处理，见 Step 6.1。
4. **不动既有行为**：窄侧栏（`siderCollapsed`）、徽标、批量全选、置顶项目拖拽的现状一律保持；改动只落在"渲染哪几行"这一层。
5. **可测优先于可读**：每条 AC 必须落到具体测试文件名 + 用例名，且该用例必须**真的会执行断言**（不接受条件永不成立的空转用例，也不接受依赖被 fake timers 覆盖的 shim 的配方）。

## Step 2 — `.../GroupedHistory/hooks/useWorkspaceExpansionState.ts`（第 3 轮定稿：store 化 + 去 localStorage）

**目标**：订阅者只有**一条**输入边且无挂载竞态；代码中**不存在** `localStorage` 读写路径。

**改动点**

1. 新增导出类型 `export type WorkspaceViewSnapshot = { expandedWorkspaces: string[]; loadedCounts: Record<string, number> };`，替换现 `:6-8` 的 `WorkspaceExpansionChangeDetail`。
2. 新增模块级 store（同文件，**零新增文件**）：
   ```
   const EMPTY_SNAPSHOT: WorkspaceViewSnapshot = { expandedWorkspaces: [], loadedCounts: {} };
   let lastSnapshot: WorkspaceViewSnapshot = EMPTY_SNAPSHOT;
   const getSnapshot = (): WorkspaceViewSnapshot => lastSnapshot;
   const subscribe = (onStoreChange: () => void): (() => void) => {
     if (typeof window === 'undefined') return () => {};
     window.addEventListener(WORKSPACE_EXPANSION_EVENT, onStoreChange);
     return () => window.removeEventListener(WORKSPACE_EXPANSION_EVENT, onStoreChange);
   };
   ```
   `lastSnapshot` 每次 dispatch 赋**新对象**、同一状态下保持同一引用 → 满足 `useSyncExternalStore` 对 `getSnapshot` 的要求。`subscribe` 必须带 `typeof window === 'undefined'` 守卫，与模块现有的 SSR 防御风格一致。
3. `dispatchWorkspaceExpansionChange`（现 `:28-38`）签名改为 `(snapshot: WorkspaceViewSnapshot)`：
   ```
   export const dispatchWorkspaceExpansionChange = (snapshot: WorkspaceViewSnapshot): void => {
     lastSnapshot = snapshot;                       // 必须在 window 守卫之前
     if (typeof window === 'undefined') return;     // 现 :29-31 的早退，位置不变
     window.dispatchEvent(new Event(WORKSPACE_EXPANSION_EVENT));
   };
   ```

   - **`lastSnapshot = snapshot;` 必须放在现有 `typeof window === 'undefined'` 早退（现 `:29-31`）之前**，否则在无 window 环境下快照永远停在 `EMPTY_SNAPSHOT`，而 `getSnapshot` 仍会被 `useSyncExternalStore` 的 server-snapshot 分支调用。
